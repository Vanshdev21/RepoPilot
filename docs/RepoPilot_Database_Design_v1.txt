1. Objectives and principles
MongoDB stores application identity, connected repository metadata, agent execution state, patch metadata, test evidence,
approvals and report data. GitHub remains the source of truth for repository content, issues, branches, commits and pull
requests. Store only the bounded context and evidence required by RepoPilot; do not mirror entire repositories.
Principle
Design decision
Source of truth
GitHub owns repository and PR state; MongoDB stores snapshots and references.
Ownership
User-owned records carry userId or are accessible only through an owned parent.
Evidence integrity
Persist base commit SHA, patch hash, actual test output metadata and timestamps.
Human approval
Approval binds to exact patch hash and base commit.
Bounded storage
Limit source excerpts, diffs, logs and event payload sizes.
Recoverability
Persist run state and ordered events so clients can recover after disconnects.
Least privilege
Never store raw credentials in ordinary user documents.
2. Architecture and relationships
 users (1) ■■■■■■■■ (many) repositories
  ■                       ■
  ■■■■■■■■■ (many) agentRuns ■■■■■■■■ (1) repositories
  ■                    ■
  ■                    ■■■ (1) report
  ■                    ■■■ (many) approvals
  ■                    ■■■ (many) agentEvents
  ■■■■■■■■■ (many) idempotencyKeys
Use ObjectId references for userId, repositoryId and runId. Embed small historical snapshots (issue title, repository fullName,
default branch and base commit SHA) inside runs/reports so reports remain understandable if GitHub metadata changes.
Ownership rule: A repository connection belongs to the user who connected it. Do not assume a globally shared repository
record unless implementing a deliberate shared-cache model.

12. Mongoose implementation guidance

payloads with Zod; Mongoose validation is a second line of defence.

13. Lifecycle and consistency
 queued -> running
           ■■■ failed
           ■■■ cancelled
           ■■■ awaiting_review
                  ■■■ completed (finalized without publishing)
                  ■■■ publishing -> completed (PR created)
                                  -> failed (publish attempt failed)
The agentRuns document is the authoritative workflow snapshot. Every stage transition should update the run and append an
event. Use MongoDB transactions where supported; otherwise use an idempotent outbox/event pattern so state and events
can be reconciled.
Patch consistency: calculate SHA-256 over a canonical patch representation and store the base commit SHA. Approval
includes both. If either changes, invalidate prior approval. Before PR creation, recompute the hash and recheck the upstream
base.
Report consistency: create/update a report as evidence becomes available. The unique runId index prevents duplicate
canonical reports. Use explicit states such as pending, not_run, passed, failed and timed_out.
14. Security and privacy
Risk
Control
Credential exposure
No raw GitHub token in user documents; encrypt token material and restrict decrypt access.
Cross-user access
Store userId and enforce ownership checks in every service query.
Prompt injection
Treat issue, README and source text as untrusted data, not instructions.
Oversized documents
Bound issue excerpts, source snippets, diffs, logs and event payloads.
Sensitive logs
Redact secrets; never persist environment variables or container credentials.
Unauthorized PR
Verify approval, patch hash and base SHA immediately before publishing.
Database exposure
Use TLS, network restrictions and separate least-privilege credentials per environment.
15. Backup and retention
Enable managed backups or scheduled snapshots. Define recovery objectives and test restoration. Use separate database
credentials for development, staging and production.
Data
Suggested starting policy
Users and repository links
Retain while account active; support account deletion.
Agent runs and reports
Retain for product history; define export/deletion policy.
Raw test output
Bound size; retain only as long as needed for report/debugging.
Agent events
Keep enough history for report and SSE recovery; optionally TTL old events.
Idempotency keys
Expire after a bounded period such as 24–72 hours.
Credential material
Delete/revoke on disconnect or account deletion; rotate after suspected compromise.
These are proposed policies, not PRD mandates. Ensure deletion covers related reports, events, artifacts and credentials.

18. Assumptions and decisions

Decision in this design

users, repositories, agentRuns and reports from PRD.
Supporting collections

Public GitHub repositories for MVP.

Proposed starting policies; product owner confirmation required.
Database design definition of done: RepoPilot can persist users, connected repositories, agent runs, real stage events,
validated patches, actual test evidence, explicit patch approvals and one auditable report per run. All user-owned records are
access-controlled and indexed for expected queries.
